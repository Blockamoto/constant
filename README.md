# Constant

Constant is the operating system for **Constant Limited**: a small, auditable company engine with a human-friendly front end.

The aim is not to turn the company into a spreadsheet maze. It is to keep the moving parts visible, make routine work automatable, and leave a durable record of what happened and why.

## First milestone

The initial platform is deliberately small:

- company setup and readiness
- obligations and recurring compliance
- finance and tax workflow
- operational automations
- an audit trail for scheduled-agent activity
- a GitHub capability smoke test for scheduled runs

The immediate company path is:

1. establish Constant Limited's operating record
2. obtain the organisation identifiers needed for third-party accounts, including D-U-N-S
3. create the organisation Play Console account
4. use that account to ship Proximity under Constant rather than an individual's public identity

## Run locally

Constant now fails closed unless authentication secrets are present.

Example:

```bash
CONSTANT_ADMIN_PASSWORD='use-a-long-unique-password' \
CONSTANT_SESSION_SECRET='use-at-least-32-random-characters-here' \
npm start
```

Then open `http://localhost:3000`.

No runtime dependencies are required.

## Deploy to Render

The root `render.yaml` is ready for a Render Blueprint.

During first Blueprint creation Render will ask you for `CONSTANT_ADMIN_PASSWORD`. The session signing secret is generated by Render automatically.

See `docs/RENDER.md` for the exact deployment steps.

## Security boundary

This repository is public. **Do not commit credentials, tax records, bank details, personal identifiers, API keys, private correspondence, or private company documents as plaintext.**

The dashboard itself is password-gated, but authentication is not a substitute for encrypted storage. Runtime passwords and keys belong in Render environment variables. Persistent sensitive records will get an explicit encrypted storage layer before they are introduced.

## Structure

- `server.mjs` - Node server, session authentication and API shell
- `public/` - authenticated Constant dashboard and login surface
- `data/` - non-sensitive operational state
- `docs/` - architecture, Render instructions, roadmap, and test protocols
